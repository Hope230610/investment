# 📄 AI投资决策助手（产品方案 V4 - 产品机制补强版）

---

# 一、产品概述

## 🎯 产品定位

> 一个帮助普通投资者降低决策错误率的 AI 投资决策辅助系统（非荐股工具）

## ❗核心原则

- 不替用户做决策
- 不提供直接买卖指令
- 强调结构化判断 + 风险控制 + 用户适配
- 优先减少错误，而非追求收益最大化

## 👤 目标用户

- A 股投资新手 / 小白
- 缺乏稳定方法论的中级投资者
- 容易受情绪影响的交易用户（追涨、恐慌卖出、频繁换股）

## 🧠 产品本质

> ❌ 选股工具  
> ✅ 决策干预系统（AI 投资教练）

系统目标是影响用户行为，而不是单纯提供信息。

---

# 二、核心设计原则

## 1️⃣ 结论优先（条件化结论）

- 输出条件化判断，而非确定性结论
- 明确适用人群、适用前提和失效条件
- 当信息不足时，优先提示“不足以判断”

## 2️⃣ 降低认知负担

- 首屏只保留 4 个以内关键判断点
- 使用自然语言解释，不要求用户先理解专业术语
- 统一以卡片化结构输出，详细推理下沉为二级信息

## 3️⃣ 可行动性

- 每个输出必须回答“用户下一步该做什么”
- 行动建议只允许使用观察、等待条件、仓位纪律、自检问题、复盘动作
- 禁止使用带有直接交易指令意味的表达

## 4️⃣ 风险优先

- 每次分析必须包含核心风险、触发条件、用户匹配风险
- 风险提示优先于收益叙事
- 高风险场景下优先给出限制条件，而不是参与建议

## 5️⃣ 用户适配

- 同一股票，不同用户可以得到不同的“适配性”和“下一步”
- 用户适配影响表达方式、风险阈值和建议动作
- 用户适配不改写底层资产事实判断

## 6️⃣ 时间维度

- 短期：1-2 周
- 中期：1-3 个月
- 长期：6-12 个月
- 每个结论都必须具备有效期和复盘时间

# 三、核心用户场景与入口

## 1️⃣ 单股咨询 `single_stock_check`

### 用户目标

- 快速判断某只股票当前是否值得继续关注
- 理解该标的与自己是否匹配

### 输入

- `stock_id`
- 可选 `user_profile`

### 输出

- 六段式决策卡片
- 关键原因
- 适配性判断

### 用户下一步

- 加入观察列表
- 等待明确条件出现
- 记录自己的关注理由，准备后续复盘

## 2️⃣ 交易前自检 `pre_trade_check`

### 用户目标

- 在准备买入、加仓、减仓或卖出前，避免情绪化操作
- 检查当前动作是否符合自己的策略和风险边界

### 输入

- `stock_id`
- `user_profile`
- 当前意图（买入 / 加仓 / 减仓 / 卖出）
- 触发原因（如利好消息、连续上涨、恐慌下跌）

### 输出

- 六段式决策卡片
- 行为偏差识别结果
- 需要满足的等待条件或自检问题

### 用户下一步

- 先完成自检问题
- 等待条件满足后再复查
- 如果是情绪触发，先进入冷静期和记录流程

## 3️⃣ 交易后复盘 `post_trade_review`

### 用户目标

- 判断本次操作的得失来自判断质量还是运气
- 积累个人投资行为模式

### 输入

- `stock_id`
- `user_profile`
- 实际操作信息（买入 / 卖出 / 持有）
- 触发原因
- 后续结果

### 输出

- 决策归因
- 行为偏差提示
- 下次遇到类似情境的改进动作

### 用户下一步

- 记录复盘结论
- 更新行为标签
- 在下次类似操作前调用交易前自检入口

# 四、系统整体架构

## 四大核心模块

1. 投资决策中心（核心判断）
2. AI 问投资（认知辅助）
3. 市场理解引擎（环境感知）
4. 投资行为分析系统（行为干预与复盘）

## 模块关系

- 投资决策中心负责生成资产判断、适配性判断和卡片化输出
- 市场理解引擎只提供环境上下文，不直接改写个股事实判断
- 投资行为分析系统负责识别情绪化行为、触发干预、沉淀复盘结果
- AI 问投资负责把复杂结论转成通俗解释，降低认知门槛

---

# 五、核心模块设计

## 1️⃣ 投资决策中心

### 🎯 目标

> 判断当前标的是否值得继续关注，以及是否适合当前用户

### 📥 输入接口

- `stock_id`
- `interaction_scenario`
- 可选 `user_profile`

### 📤 首屏输出结构（六段式卡片）

1. 一句话判断
2. 为什么
3. 适不适合我
4. 下一步
5. 主要风险
6. 复盘时间

### 📤 二级解释信息

- 数据来源
- 关键指标变化
- 五维模型拆解：质量 / 成长 / 估值 / 预期 / 市场结构
- 输出标记：`data_fact` / `model_inference` / `uncertainty`

### 设计要求

- 首屏默认不展开详细推理
- “下一步”只能给出非交易指令型建议
- 结论必须绑定适用周期和失效条件

## 2️⃣ AI 问投资

### 🎯 目标

> 降低用户理解门槛，帮助其看懂结论而非替其下决心

### 输出结构

- 一句话解释
- 通俗翻译
- 对应案例
- 用户常见误解提醒

## 3️⃣ 市场理解引擎

### 🎯 目标

> 理解市场变化，并将其映射为风险背景和环境上下文

### 输出结构

1. 发生了什么
2. 为什么发生
3. 影响行业 / 风格
4. 影响程度（高 / 中 / 低）
5. 对当前判断的影响边界

### 约束

- 只能作为上下文输入投资决策中心
- 不直接输出“因此可以买 / 卖”

## 4️⃣ 投资行为分析系统

### 🎯 目标

> 识别用户行为偏差，减少错误决策，帮助用户形成自己的投资体系

### 核心能力

1. 用户画像管理
2. 行为事件记录
3. 决策归因分析
4. 干预提醒与复盘建议

### 行为事件字段

- 操作类型
- 触发原因
- 市场状态
- 股票状态
- 用户情绪
- 结果回看

# 六、用户适配机制

## 最小画像字段 `user_profile`

- `experience_level`：新手 / 中级 / 有体系投资者
- `holding_horizon`：短期 / 中期 / 长期
- `risk_tolerance`：低 / 中 / 高
- `behavior_tag`：追涨倾向 / 恐慌卖出倾向 / 频繁换股 / 纪律稳定

## 适配逻辑

- `experience_level` 决定解释深度和默认提醒强度
- `holding_horizon` 决定使用哪个时间维度的判断结果
- `risk_tolerance` 决定风险阈值和“下一步”动作边界
- `behavior_tag` 决定是否优先触发行为干预卡片

## 未知用户默认策略

- 默认按“新手 + 中期持有 + 中低风险承受 + 无明确行为标签”处理
- 默认使用更保守的表达和更严格的风险提示
- 未知画像下不给出高参与度表述，只给观察、等待、自检、复盘建议

## 适配输出要求

- 必须明确写出“该结论更适合谁 / 不适合谁”
- 同一标的面对不同画像时，“适不适合我”和“下一步”必须可区分

---

# 七、Agent 系统设计

## 原则

- 按认知拆分，而非技术拆分
- Agent 负责生成局部判断，不直接面向用户输出最终结论

## Agent 组成

- 基本面 Agent
- 预期 Agent
- 市场结构 Agent
- 用户适配 Agent

## Agent 输出

- 结论（偏正向 / 中性 / 偏负向）
- 置信度（0-100）
- 核心理由
- 失效条件

## 决策机制

- 综合评分 = Σ（权重 × 置信度）
- 冲突处理机制：方向一致性检查 → 风险否决 → 加权汇总
- 用户适配 Agent 只调整适配性和动作建议，不改写基础事实判断

---

# 八、系统工作流程

1. 用户选择入口场景
2. 系统接收 `stock_id`、`interaction_scenario` 和可选 `user_profile`
3. 数据层获取行情、财务、市场环境信息
4. 多 Agent 完成资产判断
5. 用户适配模块生成适配性判断
6. 行为分析模块识别是否存在偏差触发
7. 投资决策中心输出六段式卡片
8. AI 问投资生成通俗解释
9. 系统记录本次决策与后续复盘时间

---

# 九、行为干预机制

## 触发场景

### 1️⃣ 追涨

- 触发条件：短时间连续上涨后，用户因涨幅或热点消息产生买入冲动
- 干预动作：提示估值位置、历史回撤概率、等待条件、自检问题
- 复盘动作：记录“为什么想立刻买”的原因，后续对照结果

### 2️⃣ 恐慌卖出

- 触发条件：快速下跌或负面新闻后，用户立即产生卖出冲动
- 干预动作：提示当前风险来源、是否已偏离原计划、是否进入情绪主导状态
- 复盘动作：记录是否因为波动而改变原策略

### 3️⃣ 频繁换股

- 触发条件：短周期内连续更换标的或逻辑跳变频繁
- 干预动作：提示交易一致性问题、原判断是否被验证、是否存在“追新故事”倾向
- 复盘动作：要求先完成上一笔操作复盘，再进入新标的分析

## 干预输出要求

- 干预优先级高于常规股票分析展示
- 干预内容以限制条件、冷静期、自检问题、复盘建议为主
- 不允许把干预话术写成交易建议

---

# 十、责任隔离与输出标记

## 输出标记

- `data_fact`：可被数据直接支持的事实结论
- `model_inference`：模型基于事实和规则形成的判断
- `uncertainty`：样本不足、信号冲突或高不确定性部分

## 用户提示

- 系统仅提供辅助分析，不构成投资建议
- 用户在高风险场景继续操作前，需要再次确认风险来源和自身假设
- 所有输出都保留适用条件和失效条件

## 审视原则

- 越接近真实交易动作，越要强化风险提示和用户自我确认
- 越高不确定性，越要减少动作表达强度

---

# 十一、时间与复盘系统

## 时间机制

- 每个结论必须绑定短期 / 中期 / 长期中的一个主周期
- 每个卡片必须给出复盘时间
- 超过有效期后，结论自动降级为“需重新评估”

## 复盘机制

- 记录当时结论、用户动作、触发原因和后续结果
- 对比“判断正确但执行错误”与“判断错误但运气好”的差异
- 输出下一次类似场景的提醒规则

---

# 十二、MVP 设计

## 目标

- 验证系统能否让用户做出更理性的投资决策

## 首版范围

- 只做三个入口：`single_stock_check`、`pre_trade_check`、`post_trade_review`
- 只服务 A 股普通投资者
- 只验证产品机制闭环，不展开复杂模型工程和自动化交易能力

## MVP 输入接口

- `stock_id`
- `interaction_scenario`
- 可选 `user_profile`

## MVP 输出

- 六段式决策卡片
- 行为偏差识别结果
- 复盘时间
- 输出标记：`data_fact` / `model_inference` / `uncertainty`

## 明确不做

- 自动下单
- 直接买卖建议
- 全市场主动推荐标的
- 过度复杂的个性化画像系统

---

# 十三、验证指标与测试场景

## 核心验证指标

1. 用户是否延迟或取消原本的冲动操作
2. 用户是否完成至少一次交易后复盘
3. 用户是否能复述结论原因与核心风险
4. 用户是否逐步形成固定的交易前自检习惯

## 产品测试场景

1. 同一股票面对新手和中级投资者时，“适不适合我”和“下一步”必须不同
2. 高风险场景下，系统必须给出风险限制和等待条件，不能出现直接买卖指令
3. 追涨和恐慌卖出触发时，系统必须先进入行为干预流程，而不是重复股票分析
4. 未知用户画像下，系统必须自动切换为保守策略
5. 结论超过有效期后，系统必须提示重新评估

---

# 十四、产品差异化

1. 决策导向，而不是信息堆叠
2. 风险优先，而不是收益故事优先
3. 用户适配，而不是统一答案
4. 行为干预，而不是只做静态分析
5. 复盘闭环，而不是一次性输出

---

# 十五、一句话总结

> 本系统不是帮助用户“选股”，而是通过“结构化分析 + 用户适配 + 行为干预 + 复盘机制”，帮助用户减少错误、提升决策质量。
