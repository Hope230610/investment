# AI 投资决策助手 MVP 功能优先级矩阵

更新时间：2026-03-26

## 1. 文档目的

本矩阵用于在产品推进过程中统一功能优先级，避免范围失控、研发分散和上线目标偏移。

本矩阵只服务于 MVP 与 v1 上线阶段，不代表中长期完整路线图。

## 2. 优先级判断原则

功能优先级不按“看起来高级”排序，而按以下标准排序：

- 是否直接支撑核心产品价值
- 是否直接影响主流程闭环
- 是否直接影响上线风险
- 是否直接影响用户理解与信任
- 是否能在当前阶段低成本验证价值
- 是否会显著增加合规和工程复杂度

## 3. 四象限定义

### 3.1 P0：必须上
定义：
- 不做就无法形成产品闭环
- 不做就不适合进入内测或灰度
- 不做会明显影响产品定位和用户信任

### 3.2 P1：应该上
定义：
- 能显著提升闭环、留存、体验或可控性
- 不做也能内测，但效果和质量会明显受限
- 建议在灰度前完成

### 3.3 P2：可以延后
定义：
- 有价值，但不是当前阶段成败关键
- 可以在内测验证后继续补
- 不适合抢占 P0/P1 资源

### 3.4 P3：明确不上
定义：
- 与当前产品定位冲突
- 会显著提高合规风险
- 会造成范围失控
- 不属于 v1 阶段应该承担的能力

## 4. P0：必须上功能

### 4.1 登录与基本身份体系
原因：
- 没有账号体系就无法形成记录、画像、复盘闭环
- 也是最基本的产品可持续使用前提

### 4.2 用户画像
原因：
- 是“适不适合我”这条产品主线成立的基础
- 也是产品差异化的重要支点

### 4.3 单股咨询
原因：
- 是最轻量、最自然的使用入口
- 是用户理解产品价值的第一场景

### 4.4 交易前自检
原因：
- 是行为干预价值的核心体现
- 是产品区别于普通股票信息工具的关键能力

### 4.5 交易后复盘
原因：
- 是长期闭环成立的核心
- 没有复盘，产品就会退化成一次性查询工具

### 4.6 统一结果页
原因：
- 是产品价值集中交付的页面
- 是风险提示、六段式卡片、解释层、复盘动作的承载中心

### 4.7 历史记录
原因：
- 没有记录页，用户无法回看自己的判断过程
- 也无法形成复盘回流

### 4.8 复盘任务
原因：
- 是促使用户回流和形成闭环的重要机制
- 是验证长期价值的关键功能

### 4.9 风险声明与边界文案
原因：
- 不做就会显著增加误解率和合规风险
- 是上线底线要求

### 4.10 数据不足降级能力
原因：
- 不做会导致用户把低质量输出当作有效判断
- 这是可信度和安全性的底层要求

### 4.11 行为干预优先逻辑
原因：
- 是产品机制核心，不是装饰功能
- 如果高风险输入下仍按普通分析展示，产品定位会失真

## 5. P1：应该上功能

### 5.1 观察列表服务端化
原因：
- 当前以本地存储为主，无法跨设备、跨会话延续
- 会直接影响长期跟踪和复盘体验

### 5.2 关注理由与复盘关联
原因：
- 可以加强“当时为什么关注”与“后来结果如何”的闭环
- 对复盘质量提升明显

### 5.3 会话恢复与 token 失效处理
原因：
- 直接影响真实用户连续使用体验
- 对灰度阶段非常重要

### 5.4 错误提示与失败态统一
原因：
- 结果页和分析流程如果失败表达不清，会迅速损害信任
- 对高风险产品尤其重要

### 5.5 最小行为埋点体系
原因：
- 没有埋点就无法知道产品到底哪里成立、哪里失效
- 这是内测和灰度阶段的必要条件

### 5.6 关键流程 smoke 与回归验证
原因：
- 没有最小测试能力，灰度阶段很容易被小改动打穿
- 属于工程质量必备能力

### 5.7 健康检查、日志与最小监控
原因：
- 没有监控就无法承接更大流量和真实事故
- 是灰度前的重要门槛

### 5.8 首页回流优化
原因：
- 首页要承担“最近分析、待复盘、画像摘要”的回流作用
- 影响二次使用和留存

## 6. P2：可以延后功能

### 6.1 更复杂的 AI 解释层
原因：
- 有价值，但不是产品成立的前提
- 当前先保证基本解释稳定更重要

### 6.2 双档解释模式
例如：
- 更简单
- 更专业

原因：
- 属于体验增强，不是 MVP 核心闭环

### 6.3 更细粒度结果状态
例如：
- partial_ready
- waiting_more_data
- confidence_low

原因：
- 对复杂度提升较大，可在主流程稳定后补充

### 6.4 更完整桌面端布局
原因：
- 当前移动端优先已足够支撑 MVP
- 体验优化可后置

### 6.5 草稿缓存和最近搜索
原因：
- 提升体验，但不影响核心价值验证

### 6.6 更复杂用户画像
例如：
- 资金规模
- 偏好行业
- 收益目标

原因：
- 过早增加画像复杂度会增加理解成本和合规风险

### 6.7 高级市场背景模块
例如：
- 风格轮动
- 宏观环境图谱
- 板块联动分析

原因：
- 不是当前产品差异化最核心的部分
- 复杂度高，容易分散重点

### 6.8 多市场支持
例如：
- 港股
- 美股
- ETF
- 基金

原因：
- 当前只服务 A 股更利于收口和验证

## 7. P3：明确不上功能

### 7.1 自动下单
原因：
- 与当前产品定位冲突
- 合规风险极高
- 工程复杂度高

### 7.2 买卖点推送
原因：
- 极易被理解为投资建议
- 明显逼近高风险监管边界

### 7.3 个股主动推荐流
原因：
- 会把工具属性带向推荐属性
- 显著增加算法与合规风险

### 7.4 热门股票榜单运营
原因：
- 容易演变为内容分发和流量运营
- 会弱化行为干预与复盘主线

### 7.5 社区讨论、跟单、观点广场
原因：
- 不适合当前阶段
- 风险、内容治理、合规成本都过高

### 7.6 收益率承诺型会员服务
原因：
- 与产品定位和合规原则冲突

### 7.7 复杂策略组合推荐
原因：
- 不是 MVP 的最短验证路径
- 容易让产品失焦

### 7.8 首页个性化推荐股票
原因：
- 会显著增加个性化推荐与算法风险
- 当前阶段应坚持用户主动输入驱动

## 8. 优先级矩阵总表

### P0：必须上
- 登录
- 用户画像
- 单股咨询
- 交易前自检
- 交易后复盘
- 统一结果页
- 历史记录
- 复盘任务
- 风险声明与边界文案
- 数据不足降级能力
- 行为干预优先逻辑

### P1：应该上
- 观察列表服务端化
- 关注理由与复盘关联
- 会话恢复与 token 处理
- 错误提示与失败态统一
- 最小行为埋点
- 关键流程 smoke / 回归验证
- 健康检查、日志、监控
- 首页回流优化

### P2：可以延后
- 更复杂解释层
- 双档解释模式
- 更细粒度结果状态
- 更完整桌面布局
- 草稿缓存和最近搜索
- 更复杂用户画像
- 高级市场背景模块
- 多市场支持

### P3：明确不上
- 自动下单
- 买卖点推送
- 个股主动推荐
- 热门股票榜单
- 社区/跟单
- 收益承诺型会员
- 复杂策略组合推荐
- 首页股票推荐流

## 9. 当前项目与矩阵的映射判断

### 9.1 当前已经具备基础的 P0 能力
- 登录
- 用户画像
- 单股咨询
- 交易前自检
- 交易后复盘
- 统一结果页
- 历史记录
- 复盘任务
- 风险声明雏形
- 行为干预雏形

### 9.2 当前仍需补齐的 P0 问题
- 生产态身份与权限边界
- 数据不足降级统一体验
- 文案统一与乱码问题
- 主链路异常态和失败态一致性
- 主流程 smoke 稳定性

### 9.3 当前最值得优先补齐的 P1
- 观察列表服务端化
- 关注理由与复盘关联
- 会话恢复和 token 处理
- 监控和日志
- 最小测试体系

## 10. 版本规划建议

### v1.0
范围：
- 只做 P0
- 选做部分关键 P1

目标：
- 完成封闭内测
- 验证产品价值

### v1.1
范围：
- 补核心 P1

目标：
- 完成灰度上线准备
- 建立更稳定闭环

### v1.2
范围：
- 选择性补 P2

目标：
- 在不破坏产品定位前提下增强体验
- 提高留存和理解度

## 11. 评审机制建议

每次新需求进入时，必须回答以下问题：
- 这个功能属于 P0 / P1 / P2 / P3 哪一类
- 它是否直接支撑核心价值
- 它是否会增加合规风险
- 它是否会抢占更关键问题的资源
- 它是否适合当前阶段验证

如果无法明确回答，不应进入当前版本。

## 12. 最终建议

当前最重要的不是“继续加功能”，而是“让 P0 和关键 P1 成立”。

只要你把：
- 决策辅助
- 行为干预
- 复盘闭环
- 风险边界
- 数据可控性

这五件事做扎实，产品就具备真正进入下一阶段的资格。
