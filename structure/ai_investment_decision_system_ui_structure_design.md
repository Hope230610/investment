# AI 投资决策助手 V4 可开发级 UI 结构设计

## 1. 文档定位

- 来源文档：`F:\investment\design\ai_investment_decision_system_v_4.md`
- 交付目标：将产品机制方案转为可交付给产品、UI、前端、后端协同开发的 UI 结构设计
- 设计范围：MVP 首版，仅覆盖 `single_stock_check`、`pre_trade_check`、`post_trade_review`
- 目标终端：移动端优先，兼容桌面 Web 响应式

## 2. 设计前提与取舍

### 2.1 设计前提

- 产品不是荐股工具，而是“决策干预系统”
- 首屏必须降低认知负担，重点只展示 4 个以内核心判断
- 行为干预优先级高于常规分析
- 所有“下一步”都必须是非交易指令
- 每个结论必须绑定有效期、失效条件、复盘时间

### 2.2 核心取舍

1. 采用“单结果页 + 场景差异化输入”而不是三套完全独立结果页。
原因：三类场景共享六段式决策卡与风险框架，统一结果容器可降低开发复杂度并保持一致认知模型。

2. 采用“移动端优先”的信息架构。
原因：A 股普通投资者高频使用移动端；首版更适合用纵向卡片流承载复杂信息。

3. 将详细推理下沉到抽屉和二级区块，而不是首屏完全展开。
原因：主目标是帮助用户做更稳健判断，不是一次性灌输全部分析细节。

4. 行为干预采用“结果页置顶警示卡 + 冷静期弹层”双机制，而不是单独新页面。
原因：能在不打断主流程的前提下优先干预冲动行为，同时避免流程过长导致流失。

## 3. 总体信息架构

### 3.1 产品地图

```text
首页
├─ 三大入口区
│  ├─ 单股咨询
│  ├─ 交易前自检
│  └─ 交易后复盘
├─ 最近使用
├─ 待复盘提醒
└─ 用户画像入口

场景输入页
├─ 股票选择
├─ 用户画像摘要
├─ 场景专属字段
└─ 提交分析

分析结果页
├─ 行为干预区（条件触发时置顶）
├─ 六段式决策主卡
├─ AI 问投资解释抽屉入口
├─ 市场背景卡
├─ 适配性与边界说明
├─ 数据来源与标记
└─ 复盘任务/保存动作

辅助页面
├─ 用户画像页
├─ 历史记录页
├─ 复盘任务页
└─ 股票搜索页
```

### 3.2 全局导航结构

MVP 建议采用 4 个一级导航：

1. `首页`
2. `复盘`
3. `记录`
4. `我的`

说明：

- `首页` 承载三大分析入口与提醒
- `复盘` 聚合到期复盘任务和交易后复盘入口
- `记录` 查看历史分析、干预、结论失效状态
- `我的` 管理用户画像、风险偏好、解释层级

### 3.3 页面路由建议

| 路由 | 页面名称 | 作用 |
| --- | --- | --- |
| `/` | 首页 | 入口选择、提醒汇总、最近使用 |
| `/profile` | 用户画像页 | 填写或编辑 `user_profile` |
| `/stock/search` | 股票搜索页 | 搜索并选择 A 股标的 |
| `/analysis/single-stock` | 单股咨询输入页 | 发起 `single_stock_check` |
| `/analysis/pre-trade` | 交易前自检输入页 | 发起 `pre_trade_check` |
| `/analysis/post-trade` | 交易后复盘输入页 | 发起 `post_trade_review` |
| `/analysis/:id/result` | 分析结果页 | 展示决策卡、干预卡、解释区 |
| `/reviews` | 复盘任务页 | 查看待复盘任务和历史复盘 |
| `/records` | 历史记录页 | 查看历史分析记录 |

## 4. 核心页面结构设计

## 4.1 首页 `/`

### 页面目标

- 让用户快速进入合适场景
- 强化“决策辅助而非荐股”的产品心智
- 拉起待办型行为，如待复盘、待自检、最近分析

### 页面模块

1. 顶部状态区
2. 三大入口卡组
3. 最近分析记录
4. 待复盘提醒
5. 用户画像摘要卡

### 低保真结构

```text
[Header]
产品标题 | 风险提示入口

[画像摘要卡]
风险承受：中低 | 持有周期：中期 | 行为标签：追涨倾向
[编辑画像]

[场景入口]
┌ 单股咨询 ┐
┌ 交易前自检 ┐
┌ 交易后复盘 ┐

[待复盘提醒]
2 条待处理
- 宁德时代 | 3 天后复盘
- 招商银行 | 今日到期

[最近分析]
- 贵州茅台 | 单股咨询 | 中期有效
- 中际旭创 | 交易前自检 | 已触发追涨提醒
```

### 关键交互

- 点击入口卡进入对应输入页
- 点击画像摘要卡进入画像配置
- 点击待复盘项目进入复盘任务详情或直接进入交易后复盘

### 状态设计

- 首次使用空状态：展示“先完善画像”和三个入口说明
- 无待复盘状态：展示“暂无到期复盘任务”
- 未登录或未建档：以默认保守画像运行并显式提示

## 4.2 用户画像页 `/profile`

### 页面目标

- 收集最小可用画像
- 明确画像影响范围，只影响表达、适配和风险边界，不改写资产事实判断

### 必填字段

| 字段 | 组件 | 选项 |
| --- | --- | --- |
| `experience_level` | 单选卡片组 | 新手 / 中级 / 有体系投资者 |
| `holding_horizon` | 分段选择器 | 短期 / 中期 / 长期 |
| `risk_tolerance` | 单选卡片组 | 低 / 中 / 高 |
| `behavior_tag` | 多选标签 | 追涨倾向 / 恐慌卖出倾向 / 频繁换股 / 纪律稳定 |

### 辅助说明

- 顶部固定说明：“画像只用于调整解释深度、风险提示和下一步建议”
- 支持“暂不填写，使用默认保守策略”

### 关键交互

- 保存后回到来源页面
- 若从分析流程进入，支持“保存并继续分析”

## 4.3 单股咨询输入页 `/analysis/single-stock`

### 页面目标

- 让用户在最少输入下快速发起“是否值得继续关注”的分析

### 表单结构

| 模块 | 字段 | 是否必填 |
| --- | --- | --- |
| 股票选择 | `stock_id` | 是 |
| 用户画像摘要 | `user_profile` | 否 |
| 分析周期偏好 | `primary_horizon` | 否 |
| 关注原因 | `focus_reason` | 否 |

### 页面模块

1. 股票搜索选择器
2. 画像摘要折叠卡
3. 可选关注原因输入框
4. 提交按钮

### 提交前文案

- 主按钮：`开始结构化分析`
- 次提示：`系统不会提供直接买卖建议`

## 4.4 交易前自检输入页 `/analysis/pre-trade`

### 页面目标

- 在用户准备采取动作前，识别其是否存在情绪化触发或逻辑缺口

### 表单结构

| 模块 | 字段 | 是否必填 |
| --- | --- | --- |
| 股票选择 | `stock_id` | 是 |
| 用户画像 | `user_profile` | 是，未填写则引导补全或使用默认 |
| 当前意图 | `intent` | 是，买入 / 加仓 / 减仓 / 卖出 |
| 触发原因 | `trigger_reason` | 是 |
| 当前情绪 | `emotion_level` | 否 |
| 原计划依据 | `original_plan` | 否 |

### 交互重点

- `trigger_reason` 优先采用标签快捷选择，保留“其他补充”
- 当选择“连续上涨”“热点消息”“快速下跌”等高风险原因时，提交前可先出现轻量预警提示

### 预判拦截

若命中高风险行为特征，可在提交前弹出确认层：

```text
系统识别到你当前可能处于情绪触发场景
建议先完成自检，再决定是否继续分析
[继续分析] [返回补充信息]
```

## 4.5 交易后复盘输入页 `/analysis/post-trade`

### 页面目标

- 帮助用户复盘“这次操作是判断问题，还是执行问题，还是运气因素”

### 表单结构

| 模块 | 字段 | 是否必填 |
| --- | --- | --- |
| 股票选择 | `stock_id` | 是 |
| 用户画像 | `user_profile` | 否 |
| 实际操作 | `action_taken` | 是 |
| 触发原因 | `trigger_reason` | 是 |
| 后续结果 | `outcome_summary` | 是 |
| 当时情绪 | `emotion_level` | 否 |
| 是否偏离原计划 | `plan_deviation` | 否 |

### 页面模块

1. 操作摘要卡
2. 复盘事实表单
3. 情绪与偏离自评
4. 提交按钮

## 4.6 分析中状态页

### 目标

- 给用户明确预期，避免把分析过程误解为交易指令生成

### 展示结构

```text
正在整理你的决策信息
1. 提取资产基础事实
2. 评估市场背景
3. 检查用户适配与行为偏差
4. 生成结构化结论
```

### 交互规则

- 分析期间不可重复提交
- 支持返回首页，但后台分析继续
- 若耗时超过 8 秒，提示“分析仍在进行，可稍后在记录中查看”

## 4.7 分析结果页 `/analysis/:id/result`

### 页面目标

- 用统一结果容器承接三类场景输出
- 首屏只呈现关键判断
- 将行为干预、风险边界、下一步动作置于高优先级

### 首屏模块顺序

1. 页面级风险说明条
2. 行为干预卡（仅命中时展示，优先级最高）
3. 六段式决策主卡
4. 适配性说明卡
5. 下一步行动卡
6. 主要风险与失效条件卡
7. 复盘时间卡
8. AI 问投资入口
9. 市场背景卡
10. 详细推理与数据来源折叠区

### 低保真结构

```text
[页面级声明]
以下内容仅为辅助分析，不构成投资建议

[行为干预卡 - 条件展示]
你当前可能处于“追涨触发”场景
建议先完成 2 个自检问题，并等待条件确认
[开始自检] [先记录原因]

[六段式决策主卡]
1. 一句话判断
2. 为什么
3. 适不适合我
4. 下一步
5. 主要风险
6. 复盘时间

[适配说明卡]
更适合谁 | 不适合谁

[下一步行动卡]
- 加入观察列表
- 记录关注理由
- 等待条件触发后复查

[风险与失效条件]
核心风险 | 失效条件 | 不确定性

[AI 问投资]
看不懂？用更通俗的话解释

[市场背景卡]
发生了什么 | 影响边界

[展开详细推理]
五维模型拆解
数据来源
输出标记
```

### 三类场景差异

| 场景 | 结果页额外模块 | 展示重点 |
| --- | --- | --- |
| `single_stock_check` | 关注理由回填区 | 值不值得继续关注、适配性 |
| `pre_trade_check` | 自检问题组、冷静期模块 | 行为偏差识别、等待条件 |
| `post_trade_review` | 归因分析区、改进动作区 | 判断质量 vs 执行质量 |

### 六段式主卡字段规范

| 段落 | 字段名 | 展示要求 |
| --- | --- | --- |
| 一句话判断 | `headline_judgement` | 20-36 字，避免买卖指令化表达 |
| 为什么 | `key_reason_summary` | 2-3 条关键原因，卡片化列出 |
| 适不适合我 | `user_fit_summary` | 明确适合人群和不适合人群 |
| 下一步 | `next_step_actions` | 最多 3 条，均为非交易动作 |
| 主要风险 | `primary_risks` | 展示风险等级、触发条件 |
| 复盘时间 | `review_at` | 给出时间点和建议复查内容 |

### 输出标记展示规则

- `data_fact`：以灰蓝标签展示
- `model_inference`：以靛青标签展示
- `uncertainty`：以橙色标签展示，并默认靠前提醒

### 详细推理区结构

1. 五维模型拆解
2. 关键指标变化
3. 数据来源列表
4. 适用周期与失效条件
5. 不确定性说明

## 4.8 AI 问投资抽屉

### 设计目标

- 不跳出结果页，避免上下文丢失
- 以“解释层”而不是“新结论层”存在

### 内容结构

| 模块 | 内容 |
| --- | --- |
| 一句话解释 | 用通俗话重述结论 |
| 概念翻译 | 将专业概念转成生活化表达 |
| 对应案例 | 给出类比场景 |
| 常见误解提醒 | 告诉用户最容易误读的点 |

### 交互规则

- 从结果页底部或主卡内入口拉起
- 支持“更简单”和“更专业”两档解释深度
- 不允许在该抽屉内出现新的动作建议

## 4.9 复盘任务页 `/reviews`

### 页面目标

- 管理待复盘事项，推动产品闭环

### 模块

1. 待复盘任务列表
2. 已完成复盘
3. 结论失效提醒

### 列表字段

| 字段 | 说明 |
| --- | --- |
| 股票名称 | 标的名称与代码 |
| 来源场景 | 单股咨询 / 交易前自检 / 交易后复盘 |
| 到期时间 | 复盘时间点 |
| 当前状态 | 待复盘 / 已完成 / 已过期 |
| 快捷动作 | 去复盘 / 查看原结论 |

## 4.10 历史记录页 `/records`

### 页面目标

- 让用户查看自己过去的分析、干预、复盘行为
- 支撑“形成稳定方法论”的产品目标

### 筛选维度

- 场景类型
- 股票
- 时间范围
- 是否触发行为干预
- 是否已过有效期

- 输入页表单草稿本地保留 24 小时
- 历史分析列表分页缓存，减少重复请求

## 8. 关键交互规则

## 8.1 行为干预优先规则

- 一旦命中追涨、恐慌卖出、频繁换股任一场景，结果页先展示 `BehaviorInterventionCard`
- 对于 `pre_trade_check`，干预卡需出现在六段式主卡之前
- 若风险级别为高，底部主按钮不显示“继续动作”含义文案，只显示“完成自检”“记录原因”“稍后再看”

## 8.2 有效期规则

- 每个结果页必须显示结论主周期
- 超过 `review_at` 后，记录页与结果页都显示“需重新评估”
- 过期结果保留阅读，但禁止继续沿用“下一步”文案

## 8.3 未知画像规则

- 若用户未填写画像，显示 `ConservativeFallbackBanner`
- 结果页明确标注：“以下结论基于默认保守画像生成”

## 8.4 数据不足规则

- 若核心事实不足，六段式主卡第一段改为“不足以形成稳定判断”
- “下一步”自动收敛为“补充信息”“等待条件”“稍后复查”

## 9. 响应式与布局规范

### 后端/BFF

- 统一返回六段式卡片结构和状态标志
- 提供复盘任务和历史记录接口

## 13. 本方案结论

该 UI 结构方案的核心不是做一个“看股票信息”的界面，而是做一个“引导用户暂停、判断、约束、复盘”的决策界面。因此整个结构以场景驱动、结果卡驱动、干预优先、复盘闭环为主线。首版用统一结果页承接三类分析任务，是当前最适合 MVP 的方案，能同时兼顾开发效率、一致体验和后续扩展性。
