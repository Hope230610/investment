# AI 投资决策助手 安全与数据治理最小方案

更新时间：2026-03-30

## 1. 文档目的

本方案用于在不追求商业化复杂度的前提下，为当前产品建立最小可上线的安全与数据治理底线。

本方案重点覆盖：

- 数据分类
- 访问控制
- 存储与传输安全
- 留存与删除
- 审计与日志脱敏

## 2. 为什么这份文档是 P0

当前产品会处理以下高敏感业务数据：

- 用户登录信息
- 用户画像
- 操作意图
- 行为标签
- 复盘记录
- 关注理由
- 可能间接映射投资偏好的行为数据

这些数据一旦被误用、越权或泄露，会直接影响用户信任和合规风险。

## 3. 数据分类

### 3.1 一级：核心身份数据

- 手机号
- 邮箱
- 密码哈希
- 会话标识

要求：

- 严格访问控制
- 不进入普通业务日志

### 3.2 二级：高敏感行为数据

- 用户画像
- 行为标签
- 交易前意图
- 交易后复盘
- 关注理由

要求：

- 只允许按用户本人或授权管理员查看
- 导出需审计

### 3.3 三级：业务过程数据

- 分析任务状态
- 复盘任务状态
- 页面访问行为

要求：

- 可用于监控和指标
- 日志侧尽量脱敏

## 4. 数据最小化原则

- 不收集与当前产品目标无关的数据
- 不提前收集资金规模、账户持仓、实名信息等非必要数据
- 画像字段保持最小集
- 高风险自由文本字段尽量限制长度

## 5. 访问控制原则

- 用户只能访问自己的业务数据
- 运营默认看脱敏数据和聚合数据
- 管理员访问敏感明细必须可审计
- 数据库直连权限仅限极少数运维/管理员

## 6. 存储安全

- 密码只存哈希
- 刷新令牌只存哈希或安全摘要
- 数据库连接必须使用独立账号
- 生产与测试数据库隔离
- 备份数据同样纳入访问控制

## 7. 传输安全

- 所有外部访问必须使用 HTTPS
- 服务间通信优先走内网
- 禁止通过明文日志或 URL 传敏感字段

## 8. 日志与脱敏

日志中禁止直接记录：

- 手机号全量
- 邮箱全量
- 密码
- token
- 大段复盘原文

日志建议保留：

- 截断后的用户标识
- 分析任务 ID
- 错误码
- 降级原因

## 9. 数据留存策略

建议初版规则：

- 登录与安全审计日志：保留 180 天
- 分析任务和分析结果：保留 180 到 365 天
- 行为埋点原始明细：保留 90 到 180 天
- 用户删除账户后，按规则触发删除或匿名化流程

说明：

- 具体期限后续可再结合法务细化
- 当前阶段至少要有明确口径，不能无限留存且无人负责

## 10. 删除与导出

最小能力要求：

- 用户可申请删除账号
- 用户可申请删除画像与行为记录
- 删除后业务侧应匿名化或物理删除可识别信息
- 如需导出个人数据，应经过身份确认

## 11. 备份与恢复

- 每日备份 PostgreSQL
- 备份文件加密保存
- 限定备份访问权限
- 每月至少恢复演练一次

## 12. 第三方依赖控制

- 外部数据源只拿业务所需字段
- 不向第三方模型或服务发送不必要的用户身份信息
- 模型输入应优先传画像标签和场景结构化字段，而不是原始身份信息

## 13. 事件响应

### P0

- 用户身份信息泄露
- 大规模复盘记录泄露
- 管理员越权导出

要求：

- 立即暂停相关访问
- 定位影响范围
- 保全日志
- 管理层和法务同步

### P1

- 局部脱敏缺失
- 局部日志记录超范围

要求：

- 当日修复
- 补充扫描

## 14. 安全基线清单

- [ ] 无默认测试账号进入生产
- [ ] 密码只存哈希
- [ ] token 不明文落日志
- [ ] 用户只能访问自己的数据
- [ ] 运营仅看脱敏或聚合数据
- [ ] 敏感导出有审计
- [ ] 数据库每日备份
- [ ] 备份访问受控
- [ ] 生产和测试环境隔离

## 15. 结论

当前阶段不需要做过度复杂的安全体系，但必须守住最小底线：

- 少收集
- 少暴露
- 可审计
- 可删除
- 可恢复

只要这五件事做到位，产品才算具备进入真实用户环境的最小安全条件。
