## Purpose

定义用户画像的**最小信息范围**、**学习闭环写入规则**和**主动反馈语义**，确保画像既能支持用户适配，又不会演变成失控的数据收集入口。本 spec 在 [原版 user-profile/spec.md](../specs/user-profile/spec.md) 基础上新增画像学习闭环层。

## Requirements

### Requirement: 用户只能管理自己的画像
系统 SHALL 提供当前用户画像的读取与更新能力，且普通用户 MUST 只能访问自己的画像数据。任何跨用户读取、批量读取或代用户修改行为都必须通过显式后台角色能力与审计控制处理。

#### Scenario: 用户更新自己的画像
- **WHEN** 已登录用户提交自己的画像更新请求
- **THEN** 系统仅更新该用户自己的画像记录，并返回更新后的标准化结果

### Requirement: 画像字段必须收口到最小集
系统 MUST 将用户画像收口到经验层级、持有周期、风险承受偏好、行为标签和画像来源这组最小必要信息。枚举值和标签口径 MUST 与统一 contract 保持一致，重复标签必须被收敛，且画像结构中不得混入手机号、邮箱、资金规模、持仓明细等非必要身份或高敏字段。

#### Scenario: 提交未定义的画像枚举值
- **WHEN** 客户端提交不在约定枚举范围内的画像字段值
- **THEN** 系统拒绝更新请求，并返回明确的参数校验错误

### Requirement: 分析任务必须锁定画像快照
系统 SHALL 在创建依赖用户画像的分析或复盘任务时保存当前画像快照，并且该快照 MUST 只包含约定的最小画像信息。任务创建后的快照不得因为用户后来修改画像而被回写，用于确保分析结果可追溯到当时的用户适配上下文。

#### Scenario: 用户修改画像后回看旧分析
- **WHEN** 用户在分析任务创建后更新了自己的画像，并再次查看旧分析结果
- **THEN** 旧分析仍关联创建当时的画像快照，而不是被新画像覆盖

### Requirement: 画像学习闭环必须基于复盘数据且经用户确认

系统 SHALL 在用户完成复盘后，将复盘内容（行为模式、情绪状态、判断质量）以**主动反馈**形式展示给用户，**行为标签的写入必须经用户显式确认**。画像更新 MUST 遵循以下规则：

#### 行为标签更新规则

- 行为标签的来源分为两类：**用户自报**（复盘表单中手动勾选）和**系统推断**（intent + trigger 组合规则推导）
- 用户自报的标签：来源标注为"本次复盘确认"
- 系统推断的标签：来源标注为具体触发条件（如"连续上涨触发 + 本次复盘确认"）
- **新增**标签必须经用户在反馈卡中点击"确认"后才写入 `UserProfile.behavior_tags`
- **移除**或**降级**标签不在本次设计范围内，由独立后续 change 处理

#### 判断质量历史规则

- 每次复盘提交时，将判断质量选择（100/50/0 分，详见 post-trade-review spec）追加到判断质量历史
- 历史用于计算：判断质量百分比（Σ分数/计入次数×100%）、7天趋势、30天均值对比
- 判断质量历史 MUST 不依赖本次反馈卡确认，独立写入（用户忽略反馈卡不影响判断质量记录）

#### 情绪历史规则

- 每次预判提交（pre-trade-check）时，追加 `{ date, emotion_level, intent, trigger }` 到情绪历史
- 情绪历史用于绘制 30 天 sparkline 和均值计算
- 情绪历史 MUST 不依赖本次反馈卡确认，独立追加

#### Scenario: 用户确认行为标签更新
- **WHEN** 用户完成 post-trade-review，收到画像学习反馈卡
- **AND** 反馈卡显示行为标签更新（如"新增 追涨倾向"）
- **AND** 用户点击"确认"
- **THEN** 系统将标签写入 `UserProfile.behavior_tags`，并记录来源
- **AND** 反馈卡关闭
- **AND** 本次复盘的判断质量追加到历史（无需确认）

#### Scenario: 用户忽略反馈卡
- **WHEN** 用户完成 post-trade-review，收到画像学习反馈卡
- **AND** 用户点击"忽略"
- **THEN** 反馈卡关闭，行为标签**不写入** `UserProfile.behavior_tags`
- **AND** 本次复盘的判断质量仍追加到历史（忽略不影响判断质量记录）

## Appendix: 画像学习反馈卡展示规范

反馈卡（LearningFeedbackCard）展示内容必须完整，不得省略任何维度：

| 模块 | 内容 | 是否必选 |
|------|------|---------|
| 行为标签更新 | 标签名 + 类型（新增/移除/升级）+ 来源说明 | 有更新时必须 |
| 判断质量主指标 | 百分比数字 + vs 历史均值差值 + 档位颜色 | 必须 |
| 判断质量评价 | 三档文字（≥80%/60-80%/<60%）| 必须 |
| 判断质量趋势 | 近7天提升/下滑/稳定 + 描述文字 | 必须 |
| 判断构成 | 四分类横向柱状图（判断/部分/运气/难以区分）| 必须 |
| 情绪趋势 | 30天 sparkline + 均值 + 本次值 + 预警 | 有历史时必须 |
| 建议文案 | 基于档位的可执行建议 | 必须 |
